# 진행도 보고

패널과 캐릭터는 세션·턴 이벤트로 자동 표시된다. 단순 답변에는 표시를 위해 별도 계획이나 도구 호출을 만들지 않는다.

여러 단계 작업에서는 `mcp__mirang-progress__progress`가 제공되는지 확인하고 다음처럼 보고한다.

1. 시작: 짧은 한국어 `title`, 실제 계획 단계 수 `total`, `done: 0`, `phase: "plan"`.
2. 단계 완료: 같은 작업은 제목을 유지하고 실제 완료한 `done`만 갱신한다. 설계는 `design`, 실행은 `delegate`, 검증은 `review`를 쓴다. `delegate`라는 표시 값이 에이전트 생성을 요구하지는 않는다.
3. 종료: 맡은 범위와 검증이 실제 완료됐을 때만 `finished: true`를 보고한다. 사용자 답변 대기·오류·중단은 완료로 보고하지 않는다. 범위가 바뀌면 단계 수를 정직하게 수정한다.

예: 직접 파일을 조사·수정·검증하는 작업은 시작에 `{ "title": "설정 정리", "total": 3, "done": 0, "phase": "plan" }`, 조사 후 `{ "done": 1, "phase": "delegate" }`, 검사 중 `{ "done": 2, "phase": "review" }`, 전부 완료 후 `{ "done": 3, "finished": true }`.

- 제목이 달라지면 새 작업으로 초기화된다. 이전 작업의 수치를 이어 쓸 때 제목을 바꾸지 않는다.
- `tasks`는 실제 Agent 도구로 배정할 계획에만 쓴다. 직접 작업이나 별도 전체 세션을 가짜 예정 subagent로 등록하지 않는다.
- 하위 에이전트는 `mcp__mirang-progress__step`으로 자기 `total`, `done`, 짧은 `note`만 보고한다. 메인 전체 진행은 수정하지 않는다.
- 이 패널은 진행을 보여 주기만 한다. 작업을 나누는 방식이나 완료 판단은 사용 중인 개발 절차와 사용자의 지시를 따르며, 진행 표시 때문에 새 절차나 작업자를 만들지 않는다.
- 도구가 없으면 표시 연결 문제를 알리고 원래 작업은 진행한다. 단계 미보고 시 임의의 퍼센트를 만들어내지 않는다.
- 패널 다시 열기: `/work-progress open`. 별도 전체 세션의 내부 진행은 각 세션에서 표시하며 부모 패널에 자동 집계되지는 않는다.
